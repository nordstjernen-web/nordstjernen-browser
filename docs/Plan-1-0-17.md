Nordstjernen 1.0.17 — development-cycle plan
============================================

Snapshot: **1.0.17-dev**, 2026-06-27. A prioritized focus list for the
1.0.17 cycle, derived from a full pass over the source tree and the
project's own scoreboards. Every item below is anchored to concrete
`file:line` evidence so it can be checked before it is picked up.

The spine of the cycle is six high-conviction moves, in order, followed
by a "finish the half-built" tail and a set of scoped down-payments on
the big multi-cycle items. Because the project ships **no automated test
suite by policy**, every change is a manual-verify event — the single
most leveraged item here (rank 4) is the closest thing to a safety net
that still respects that policy.

Status legend: severity (high/med/low) · effort (small/med/large) · ROI.

**Progress (2026-06-27):** ranks 2–4 shipped in 1.0.17-dev — proxy leaks +
renderer propagation (`c04c432`), final-redirect CSP/mixed-content re-check
(`4dc609b`), and the ASan/UBSan + libFuzzer safety net (`a50dcd2`, hardened
in `0f18b66`). The security cluster is closed and the perf work is unblocked.
Quick wins landed (`a46f92c`): microtask drain-to-empty, the Android stub-APK
CI guard, and macOS/Qt behavioural smoke gates. Rank 7 (`fba3262`): dom/events
passive-by-default + body→window handler reflection (activation deferred).
Rank 8 (`b65631a`, hardened `fdea766`): the Selection API on `NdRange`
(programmatic selection now works; the C stub stays as the engine-highlight
fallback; boundary points and cross-tree extents are now validated).


## Headline themes

1. **Make the WPT scoreboard honest, then aim at the one real lever
   (URL/IDNA).** `scripts/wpt-score.sh` sums non-passing subtests with no
   `/tentative/` exclusion, so the ROI table's top rows are inflated by
   explicit non-goals — `dom/ranges` "gain 180" is ~179 tentative
   `OpaqueRange` subtests, `WebCryptoAPI/digest` "gain 371" is tentative
   cSHAKE/KangarooTwelve/TurboSHAKE that the doc itself calls out of scope
   (`docs/wpt-scores.md:108,111,149`). After the filter, the genuine top
   lever is URL/IDNA (~870 real `toascii` + `IdnaTestV2` subtests) in the
   heavily-modified in-tree lexbor `idna.c`.

2. **Close the security cluster: proxy leaks first, then redirect
   re-validation.** WebSocket / EventSource / the audio helper apply TLS
   but never the configured proxy, silently defeating the documented Tor
   recipe. Redirect re-validation splits into a cheap final-URL re-check
   (lands now) and a larger per-hop loop (deferred).

3. **Build the safety net before the risky perf work.** Three audit
   commits in one day fixed the same length-overflow / detach-during-
   `valueOf` / unbounded-queue pattern by hand; there is zero
   asan/ubsan/fuzz/valgrind tooling. A sanitizer build of the *existing*
   headless+WPT path is not a test suite and respects the no-tests-dir
   policy — and it must land before the `:has()` restyle scoping, whose
   intermittent stale-paint failure mode is exactly what manual
   verification misses worst.

4. **Auditability is a stated design constraint, not a nice-to-have.**
   `src/js.c` is 40,373 lines and owns timers, workers, XHR/fetch, custom
   elements, WebCrypto marshalling and iframe scoping. CLAUDE.md elevates
   "readable and auditable by a single human" to a design constraint, and
   the recurring security bugs land in exactly this file — so a scoped
   one-subsystem extraction earns a real rank, not a footnote.

5. **Finish the half-built.** Selection is a live no-op C stub (Range is
   fully built); module workers throw; `video.currentTime` seek,
   `wrapKey`/`unwrapKey`, and `CompressionStream` advertise support they
   don't deliver. Each is contained and high-payoff.

### 1 — Make the WPT scoreboard honest  ·  docs · high · small · high

- **First steps:** exclude subtest paths containing `/tentative/` (and the

### 2 — Route WebSocket / EventSource / audio through the proxy + app TLS  ·  ✅ DONE (1.0.17-dev)

A silent deanonymization leak that directly contradicts shipped docs.

- **Status — done (commit `c04c432`).** Both `ws.c` worker paths and
  `eventsource.c` now apply `ns_net_apply_curl_proxy`; the audio helper is
  spawned with the proxy + CA in its environment (`procview.c`). The
  `--proxy` override turned out to be more than "small": it only lived in
  the shell's `g_proxy_override` and never reached the per-tab **renderer**
  (a separate process) that actually opens WebSocket/EventSource — so the
  fix also exports `NS_HTTP_PROXY`/`NS_HTTPS_PROXY`, which `config.c` loads
  in every process. Hardening: `wss://` is now treated as TLS in the proxy
  picker, and the audio override forces the scheme-specific vars so an
  inherited `http_proxy` can't win. **Verified** at runtime with a logging
  proxy in both single- and multi-process mode — wss/ws/SSE all route
  through the proxy. **Effort was med, not small** (the renderer-propagation
  gap an adversarial review caught). **Follow-on still open:** fail-closed
  Tor egress + the Landlock net jail (`Tor.md` §5 steps 1 & 3) — this fix
  *routes* through the proxy but does not yet *refuse* direct connections.

- **Evidence:** `src/ws.c:437` and `:939`, and `src/eventsource.c:324`,
  call `ns_net_apply_curl_tls` but never `ns_net_apply_curl_proxy`; the
  audio helper (`src/audio/main.c`) calls neither. The helper exists at
  `src/net.c:1843` and is wired only by the main fetch at `net.c:4943`.
  `docs/Proxy.md:144-145` explicitly promises WebSocket is tunneled through
  the same proxy. On the documented Tor recipe
  (`--proxy=socks5h://127.0.0.1:9050`) every `ws://`, `wss://`, SSE and
  remote-audio connection currently goes out direct, because libcurl only
  auto-detects lowercase env proxies, not the browser's `--proxy` flag.
- **First steps:** add `ns_net_apply_curl_proxy(curl, url)` after the
  existing TLS apply at each of the ~4 `curl_easy_init` sites, plus
  `ns_net_apply_curl_tls` in the audio helper; smoke-test with
  `--proxy=socks5h://…` against a `wss` echo and an SSE endpoint.

### 3 — Re-validate CSP / mixed-content on the final redirect URL  ·  ✅ DONE (1.0.17-dev)

The cheap, lands-now half of redirect re-validation.

- **Status — done (commit `4dc609b`).** `fetch()` and XHR now re-run the
  connect-src CSP + mixed-content check on `resp->final_url` before delivery
  (shared `ns_final_url_connect_blocked` helper): fetch rejects, XHR yields an
  opaque blocked response; dedicated workers already did this. **Scope
  landed:** fetch + XHR (the connect-src paths); `img-src` subresources and
  full per-hop enforcement remain the deferred larger work. **Verified** at
  runtime — a `connect-src` page whose same-origin fetch 302-redirects to a
  disallowed origin is blocked, the body never delivered.
- **Evidence:** `src/js.c:6470-6492` checks mixed content and
  `ns_csp_allows(NS_CSP_CONNECT,…)` only on the pre-redirect URL, then
  `net.c:4267` sets `CURLOPT_FOLLOWLOCATION` and the final URL is never
  re-validated. `net.c` already exposes `resp->final_url` (`:4568`) and
  `location_out` (`:4663`).
- **Nuance:** the worker loader (`js.c:15215`) re-checks *only* the final
  URL after curl has already followed the whole chain — it does **not**
  validate intermediate hops, so a `self→attacker→self` redirect still
  passes. So "mirror the worker" is the **cheap increment**, not the full
  fix: re-running CSP + mixed-content + SafeBrowsing on `resp->final_url`
  catches the common `https→http` downgrade and final-origin exfil and
  reuses machinery `net.c` already exposes. Full per-hop enforcement is
  separately-scoped larger work, deferred.
- **First steps:** for fetch/XHR/`img-src` subresource fetches, after the
  request returns, re-run the allow-checks on `resp->final_url` before
  delivering the body; verify with a page that fetches an `https→http` and
  a same→cross-origin redirect.

### 4 — ASan/UBSan headless build + libFuzzer harness  ·  ✅ DONE (1.0.17-dev)

The missing safety net. **Landed before the `:has()` work (big bet 2).**

- **Status — done (commit `a50dcd2`).** Without a `tests/` dir:
  `scripts/sanitize.sh` runs an ASan+UBSan build over the existing in-process
  `--headless --dump` path across `data/render-tests`; `fuzz/fuzz_html.c` +
  `fuzz/fuzz_url.c` + `scripts/fuzz.sh` are coverage-guided libFuzzer
  harnesses over the lexbor HTML and WHATWG URL parsers (linked against a
  SanitizerCoverage-instrumented liblexbor); `.github/workflows/sanitize.yml`
  is an advisory, non-blocking CI job. **Verified** locally — both fuzzers
  build and run coverage-guided (HTML 1267→4211 edges, URL 336→1709) with no
  findings. **This satisfies the sequencing constraint and unblocks the
  `:has()` perf work.** Next fuzz targets (the plan's priority): the CSS
  tokenizer and the `src/ext.c` filter-list parser.
- **Evidence:** a grep for `asan|ubsan|fuzz|valgrind|sanitize` across
  `meson.build` and `scripts/` returns nothing. Three audit commits in one
  day (`0dea3e5`, `3d9f1a3`, `9421b60`) fixed the same overflow / detach /
  unbounded-queue pattern by hand; ~185 reactive depth-guard sites exist in
  `src/js.c`. `src/ext.c` (1251 lines, 4 commits old) parses
  attacker-adjacent remote EasyList/ABP bytes.
- **Why:** the maintainer is catching this bug class one-at-a-time by
  manual audit because nothing systematically exercises the binding/parser
  surface. A `-Db_sanitize=address,undefined` build over the existing
  headless WPT slice, plus a small libFuzzer harness over `ns_url_parse` /
  the HTML parser / the CSS tokenizer / JS argument marshalling, converts
  recurring hand-finds into build-time failures. It sanitizes the
  **existing** run path — not a new test suite.
- **First steps:** add a `scripts/` wrapper that configures a second
  builddir with sanitizers and runs the headless WPT slice under it; add a
  tiny libFuzzer target and point it at `src/ext.c` filter-list parsing
  first; wire the sanitizer build as a non-blocking CI job.

### 8 — Selection API on the existing `NdRange` polyfill  ·  ✅ DONE (1.0.17-dev)

- **Status — done (commit `b65631a`, hardened `fdea766`).** A real
  `NdSelection` (singleton) layered on `NdRange` in `data/js/polyfills.js`:
  `collapse`/`setPosition`, `collapseToStart`/`End`, `extend`,
  `setBaseAndExtent`, `selectAllChildren`,
  `addRange`/`removeRange`/`removeAllRanges`/`empty`, live `getRangeAt`,
  `containsNode`, `deleteFromDocument`, `toString` — with correct
  anchor/focus/direction and the spec `IndexSizeError`/`InvalidStateError`
  throws. The C `getSelection` was **kept as a fallback** (not deleted): when
  no range is set programmatically the readers delegate to it, so the engine
  user-highlight `toString`/`getRangeAt` still work. Pure-JS change, no C.
  **Verified** headless on a `contenteditable` page (selectAllChildren,
  collapse, forward+backward extend, setBaseAndExtent, getRangeAt identity,
  add-when-occupied, and the error/edge cases).
- **Hardening (`fdea766`, post-review).** `collapse`/`extend`/`setBaseAndExtent`
  now route offsets through the same `checkBoundary` the Range setters use, so a
  negative/over-length offset throws `IndexSizeError` and a `DocumentType` node
  throws `InvalidNodeTypeError` (previously `offset | 0` stored a bad offset
  silently); `extend`/`setBaseAndExtent` whose anchor and focus live in
  different trees now throw `WrongDocumentError` instead of building an
  incoherent backward range from a meaningless boundary comparison. A 26-case
  headless guard suite (boundary errors, cross-tree guards, forward/backward
  extent, addRange identity, removeRange) is green. **Deliberately kept**
  `getRangeAt` returning the *live* `_range`, not a clone: the review suggested
  cloning to insulate the internal direction snapshot, but cloning would break
  the spec/browser `addRange(r); getRangeAt(0) === r` identity **and**
  `removeRange(getRangeAt(0))` — two concrete round-trips — to guard a
  theoretical, browser-divergent desync. Live range wins.
- **Scope cut:** `selectionchange` events are not yet fired on programmatic
  mutation, and a prior programmatic selection shadows later user highlights
  until `removeAllRanges()` — both need a C-side selection-change signal
  (follow-up, out of scope for a JS-only change).
- **Evidence:** `src/js.c` binds all Selection methods
  (`addRange`/`collapse`/`extend`/`setBaseAndExtent`/`getRangeAt`) to the
  no-op handler with `anchorNode`/`focusNode` always `null`; `Selection`
  appears **0** times in `data/js/polyfills.js`, so unlike Range there is
  no polyfill override — the no-op C stub is the live implementation.
- **Why:** rich-text editors, copy-helpers and highlight features call
  Selection; `getSelection().toString()` works but everything stateful is
  silently dropped. Because Range already exists in `polyfills.js`
  (`NdRange`), a Selection polyfill layers on the same machinery.
- **First steps:** add a Selection polyfill in `data/js/polyfills.js`
  backed by `NdRange`/`__ndCreateRange`, route `getSelection()` to it, and
  retire the dead C no-op stub; verify with a `contenteditable` page
  calling `collapse`/`extend`/`getRangeAt`.

### 9 — Module workers  ·  feature · med · med · med

- **Evidence:** `src/js.c:16241` throws
  `TypeError: Worker: module workers are not supported` for any non-classic
  type. Dedicated classic workers (with `importScripts`/`fetch`/
  `crypto.subtle`) already work, and the engine already runs module scripts
  on the main realm (`ns_script_type_is_module`, `js.c:38334`).
- **Why:** `new Worker(url, {type:'module'})` is now the default in Vite
  and bundleless-ESM tooling, so the classic-only limitation silently
  breaks a growing share of real sites. Both halves (worker plumbing,
  module evaluation) already exist; the increment is joining them.
  SharedWorker stays unsupported.
- **First steps:** in the Worker constructor, accept `type:'module'` and
  route the entry script through the existing module-evaluation path in the
  worker realm; verify with a Vite-style
  `new Worker(new URL('./w.js', import.meta.url), {type:'module'})` that
  imports a sibling ESM module.

### 10 — Small high-confidence correctness bundle  ·  correctness · med · med · high

Self-contained fixes, each closing a latent gap where the surface
advertises support it doesn't deliver.

- **`video.currentTime` seek:** `js.c:30261` is a no-op setter;
  `video_decode.c:194` only seeks to 0. Wire a `seek <token> <t>` command
  from a `currentTime` assignment to `av_seek_frame` and the audio helper.
- **`wrapKey`/`unwrapKey`:** usages are parsed (`js.c:7380-7381`) but no
  method is bound (`js.c:16030-16039`); AES-KW is absent from
  `webcrypto.c`. Implement as `importKey` + `encrypt`/`decrypt`
  compositions plus AES-KW.
- **`CompressionStream`/`DecompressionStream`:** absent though
  `ReadableStream`/`TransformStream` exist (`js.c:37177-37179`) and zlib is
  already linked. Add as a thin `TransformStream` over zlib.
- **Microtask drain cap:** `js.c:883` `int safety = 100000` drops pending
  jobs on exhaustion — a genuine "checkpoint must drain to empty"
  deviation. Remove the counter and rely on the existing
  `eval_deadline_us` wall-clock guard.
- **Aggregate IDB cap:** per-database pages are capped
  (`NS_IDB_MAX_PAGES = 65536`, `idb.c:170`) but a page can open many named
  DBs. Add an aggregate per-origin page budget. (Note: `localStorage`
  already enforces a 5 MiB quota and the HTTP cache has `evict_to_cap`, so
  storage is **not** an unbounded-DoS dimension — this is the only real
  residual.)

## Big bets (scoped down-payments, not single-cycle big-bangs)

- **lexbor IDNA/UTS-46** (rank 6) — the biggest honest WPT lever, partly
  self-inflicted via the locally-modified `unicode/idna.c`.
- **Scope the `:has()`/`@container` incremental-restyle disable** to
  affected subtrees instead of the whole page (`css.c:15695-15700`) to
  restore the already-built −28% fast path. **Treat this as a research
  spike, not a confident "restore the machinery":** correct `:has()`
  *invalidation-set* computation is the hardest problem in incremental CSS
  (a deep change can flip an arbitrary ancestor's match state), and
  `g_has_memo` memoizes match *results*, not the invalidation set. Its
  failure mode is intermittent stale paint — so it **must follow rank 4**
  and sits below the security cluster, not parallel to it.
- **Subtree-local relayout:** every restyle currently rebuilds the entire
  layout tree (`libnordstjernen.c:137` → `engine.c:404`), and hover is
  rate-limited to the relayout cost as a band-aid
  (`libnordstjernen.c:1056`). Dirty-flag the changed box's containing block
  and re-lay just that. Large surgery, high everyday-interaction payoff;
  natural follow-on to the `:has()` scoping.
- **Credential-less renderer broker** (`tab-isolation.md` steps 3-7): the
  renderer still holds the cookie jar, cache, history and full network
  egress (`libnordstjernen.c:467-469`; seccomp permits `socket`/`connect`).
  Too large for one cycle — the right 1.0.17 down-payment is **specifying
  the broker IPC message surface** (step 6), not building it.
- **i18n fill-in:** only 27 of 98 `ns_i18n` strings are translated even in
  the best (German) catalogue, and 27 of 40 `.lang` files are 2-key
  placeholders. Mechanical, high-visibility for an OS-language-aware
  browser; pair with a `scripts/` extract-and-diff helper so coverage is
  CI-measurable, and prune or flag the placeholder languages.


## Headline ambitions: Tor, YouTube, and a Communicator-style mail client

Three large, explicitly-requested features. They differ enormously in
feasibility and in how they sit against the project ethos, so the scope is
documented honestly here before any is picked up. Only the Tor work is
realistically a 1.0.17-cycle item; the other two are product-scope
decisions, not feature drops.

### Tor network support  ·  partly shippable in 1.0.17

Status: the plumbing already exists — `--proxy=socks5h://127.0.0.1:9050`
routes traffic through a running Tor daemon (`docs/Tor.md`,
`docs/Proxy.md`), and `ns_net_apply_curl_proxy` (`net.c:1843`) applies it to
the main fetch.

What 1.0.17 can realistically land (mostly the rank-2 security work):

- A `--tor` convenience mode that defaults the SOCKS5h proxy (remote DNS, so
  no DNS leak) and tightens privacy defaults, instead of making the user
  type the full proxy URL.
- ✅ *Done (1.0.17-dev, rank 2):* the proxy leaks are closed — WebSocket,
  EventSource and the audio helper now route through the configured proxy,
  and `--proxy` is forwarded to every per-tab renderer via
  `NS_HTTP_PROXY`/`NS_HTTPS_PROXY`. (Still routes-through, not yet
  fail-closed — see §5 below.)
- A visible "Tor" status indicator in the shell, plus a bootstrap/health
  check against the SOCKS port.

Larger, later: per-tab stream isolation (a distinct SOCKS credential per
first-party origin), `.onion` handling, and a "New identity" control. Keep
the Tor daemon **external** — bundling and supervising `tor` is a heavy
dependency that cuts against the minimal-footprint ethos; integrate over
SOCKS, don't vendor it.

### "Working YouTube"  ·  conflicts with a stated non-goal

Reality check: `youtube.com` does not serve a plain file a `<video src>`
can play. It streams adaptive DASH segments through **MSE**
(`MediaSource`/`SourceBuffer`) in VP9/AV1, and MSE is an explicit non-goal
(CLAUDE.md, and the watch-outs below). So "embedded, working YouTube" is not
a small feature — it is a decision to build a media stack.

**What DASH and MSE are.** *MSE (Media Source Extensions)* is a JavaScript
API (`MediaSource` / `SourceBuffer`) that lets a page's own script feed
encoded media bytes into a `<video>` element chunk by chunk, instead of
pointing it at a file with `src` — the page, not the browser, drives the
fetching and buffering:

```js
const ms = new MediaSource();
video.src = URL.createObjectURL(ms);            // JS-driven source
const sb = ms.addSourceBuffer('video/mp4; codecs="vp9"');
sb.appendBuffer(nextSegmentBytes);              // hand the decoder bytes
```

*DASH (Dynamic Adaptive Streaming over HTTP, MPEG-DASH)* is the matching
delivery format: the video is cut into short segments (~2–10 s) encoded at
several quality levels, all listed in an XML manifest (an MPD). The player
fetches segments one at a time and switches quality to match the current
bandwidth ("adaptive bitrate"), so a slow link drops to a lower rendition
instead of stalling. (HLS is Apple's near-identical `.m3u8` equivalent.)
YouTube combines the two — its player uses MSE to append DASH segments — so
there is **no single URL** a `<video src>` can play; the "video" exists only
as the player stitching thousands of segments together at runtime. That is
why supporting it means a fragmented-MP4/WebM demuxer that accepts arbitrary
appended byte ranges, plus A/V sync, cross-segment seeking and buffer
management — i.e. the media stack the project deliberately avoids.

Two honest paths, chosen deliberately:

- **Override the non-goal (large, ongoing):** implement MSE/SourceBuffer
  over the existing libav decode path plus a DASH/HLS segment fetcher. A
  multi-cycle effort with continuous maintenance as YouTube's player
  changes, pulling the project toward the media stack it deliberately
  avoids. Only worth it if "daily-driver for video sites" becomes an
  explicit product goal.
- **Stay on-ethos (small, best-effort):** resolve a progressive/muxed
  stream URL and either play it through the existing `<video>` path or hand
  the media URL to an external player — the handoff already exists
  (`ns_media_try_launch`, `src/media.c`). Fragile (breaks when YouTube
  rotates formats) and is "open this video", not "embedded YouTube", but it
  respects the minimalism constraint.

Recommendation: keep MSE a non-goal for now; if YouTube must work, ship the
external-player / stream-resolver handoff documented as best-effort, rather
than committing to a DASH+MSE stack.

### POP/IMAP mail client, Netscape-Communicator style  ·  a separate bundled app

Reality check: a Messenger-style client is IMAP4 + POP3 + SMTP, MIME/RFC822
parsing, a local mail store, a three-pane UI (folders / message list /
reader), a compose window, and credential storage. That is a sizeable
application bolted onto the browser and directly stretches the "small enough
for one person to audit end-to-end" constraint.

What is genuinely tractable, in increasing size:

- **Protocol layer is mostly free:** libcurl already speaks `imaps://`,
  `pop3s://` and `smtp://`, so fetching folders/messages and sending mail
  needs no new network stack — only wiring over the existing curl plumbing.
- **MVP (`about:mail`, read-only):** configure one IMAPS account, list
  folders, list a folder's messages, fetch and render one message (minimal
  MIME: `text/plain` + `text/html` + basic multipart). Credentials in the
  existing config/secret store. A real, bounded first step.
- **Full Communicator Messenger (long-horizon):** compose+send over SMTP,
  multiple accounts, an offline/cached store, search, address book, filter
  rules, HTML-mail sanitization. Multi-cycle, and a deliberate expansion of
  the product's audit surface.

Ethos note: bundling mail is exactly the kind of scope Netscape took on and
modern minimal browsers do not. It is a legitimate product direction, but a
*product* decision — decide whether Nordstjernen wants to be a browser or a
Communicator-style suite before investing past the `about:mail` MVP.


## Watch-outs & non-goals

- **Don't steer by the raw WPT ROI table before rank 1 lands** — its top
  two rows credit tentative SHA-3/cSHAKE/K12 and `OpaqueRange`, explicit
  non-goals.
- **`https`-redirect pinning must be conditional** on the request having
  started `https`, or it breaks currently-working plain-http SSE.
- **Sequence rank 4 strictly before the `:has()` scoping.** Its
  intermittent, input-dependent stale-paint bugs are exactly what the
  no-automated-test policy makes nearly invisible to manual verification.
- **Storage is already bounded** — `localStorage` 5 MiB quota
  (`js.c:1965-2058`), HTTP cache `evict_to_cap` (`cache.c:644`), per-IDB-DB
  page cap (`idb.c:170`). The only residual is an aggregate per-origin IDB
  cap (folded into rank 10), not a headline DoS dimension.
- **The no-JIT interpreter is not a perf bug** — it is a deliberate W^X
  security choice. All measured perf wins to date are in the CSS cascade,
  not `js.c`; aim perf work there (the `:has()` and subtree-relayout bets).
- **Flex baseline is not a quick win** — baseline alignment needs each
  item's first line-box ascent, a post-layout used value, so it is a second
  pass bolted onto a deliberately single-pass flex implementation
  (`layout.c:7339-7363`). The cheap part is only the doc correction.
- **innerText layout-accuracy** (122-126 subtests) looks dense but is
  deeply layout-coupled for largely whitespace edge cases — high subtest
  count, low product impact. Don't let its WPT number pull it above
  URL/IDNA.
- **Next audit hot-spots:** `src/ext.c` (filter-list parser, 4 commits old)
  and `src/webgpu.c` (already produced one detach-during-`valueOf`
  finding) — fast-written code over attacker-adjacent bytes. Route both
  through the rank-4 harness first.
- **Editing the right layer:** Range/TreeWalker/NodeIterator are **live in
  `data/js/polyfills.js`** and the C path is dead — edit the polyfill, not
  the C stub. Selection is the exception (its C stub is live), so it must
  be implemented (rank 8), not edited away.
- **Conscious non-goals:** Web Audio synthesis, MSE/SourceBuffer,
  getUserMedia/RTC, and full WebGPU completion — large and against the
  no-media-stack ethos, or behind an experimental opt-in gate. One cheap
  honesty fix: make `getByteFrequencyData` return zeros instead of throwing
  so loose `try/catch` visualizers don't break.
- **Every fix is a manual-verify event** — budget smoke-launch time per
  change and use `--headless --dump` against `data/render-tests` fixtures.
